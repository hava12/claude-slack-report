# 확인 결과를 Slack으로 보내기

아래 명령의 `run.sh`는 이 스킬 폴더(이 문서와 같은 폴더)에 있는 파일이다. 처음 실행할 때 그래프·엑셀 라이브러리를 `~/.cache/slack-report/venv`에 설치한다.

## 절대 규칙
- **조회만 한다.** 실행하는 쿼리는 `SELECT`(`WITH … SELECT` 포함)·`SHOW`·`DESCRIBE`·`EXPLAIN` 한 문장뿐이다.
- **추가·수정·삭제(CUD)와 구조 변경 쿼리는 어떤 경우에도 실행하지 않는다.** `INSERT`·`UPDATE`·`DELETE`·`MERGE`·`REPLACE`·`CREATE`·`ALTER`·`DROP`·`TRUNCATE`·`GRANT`·`CALL` 등이다. 사용자가 시켜도 이 스킬에서는 하지 않고, 하지 않는 까닭을 말한다.
- 행을 잠그는 `FOR UPDATE`·`FOR SHARE`, 결과를 어딘가에 쓰는 `INTO`, 여러 문장(`;`), 주석도 쓰지 않는다.
- 조회 도구가 가진 쓰기 기능(메타베이스의 질문·대시보드·컬렉션 만들기·고치기, 모델 액션 등)도 쓰지 않는다.
- 이름·전화번호·이메일 같은 개인정보 칸은 고르지 않는다(집계 위주).
- 사용자 승인 없이 Slack에 보내지 않는다.

## 순서
1. **쿼리 쓰기**: 네이티브 SQL 한 문장을 작업 폴더에 `<이름>.sql`로 저장한다. 줄바꿈·들여쓰기로 읽기 쉽게 쓰고, 열 이름은 알아보기 쉬운 별칭(`AS 센터`)을 붙인다. 테이블·열 이름은 짐작하지 말고 조회 도구(메타베이스의 테이블 목록 등)로 확인한다.
2. **쿼리 검사**: `run.sh --check-sql <이름>.sql`을 통과한 쿼리만 실행한다. 쿼리를 고치면 다시 검사한다.
3. **실행**: 검사를 통과한 쿼리를 글자 하나 바꾸지 않고 조회 도구로 실행한다. 결과가 너무 많으면 묶어서(`GROUP BY`) 줄인 쿼리로 1번부터 다시 한다.
4. **저장**: 결과를 머리줄 있는 CSV(UTF-8)로 저장한다.
5. **미리 만들기**: `--dry-run`으로 파일만 만들고, 그래프는 Read로 직접 본다.
   ```
   run.sh --title "<무엇> (<날짜>)" --summary "<한두 줄 요약>" --data <csv> --sql <sql> --db "<DB 이름>" \
     [--chart bar|line --x <열> --y <열>[,<열>] [--top <N>]] --dry-run
   ```
   - 그래프: 항목 비교는 `bar`, 날짜 흐름은 `line`이다. 항목이 많으면 `--top`으로 그래프에만 상위 N개를 그린다(엑셀에는 전부). 목록처럼 그래프가 의미 없으면 `--chart`를 뺀다.
6. **확인받기**: 채널, 보낼 글, 쿼리, 그래프, 행 수를 보여 주고 승인을 받는다.
7. **보내기**: 같은 명령에서 `--dry-run` 대신 `--send`(설정의 기본 채널)를 붙여 실행한다. 사용자가 다른 채널을 말하면 `--channel <채널 ID>`. 기본 채널이 없으면 채널 ID를 묻는다.

## 보내는 메시지
- 글: 제목, 요약, **사용한 쿼리** 안내(DB 이름). 쿼리 본문은 글에 넣지 않는다.
- 글 맨 끝에는 항상 작은 글씨로 `made by hudson and metabase mcp`가 붙는다(Slack context 블록, `slack_report.py`의 `FOOTER`).
- 첨부: 그래프(PNG), 엑셀(전체 행), 쿼리(`<제목>.sql`). Slack 글에는 접기·펴기가 없어서 쿼리는 항상 파일로 붙인다. Slack에서는 앞 몇 줄만 보이고, 누르면 전체가 펼쳐진다.
- 표를 글에서 바로 보여야 하면(행이 몇 개뿐일 때) 요약 안에 코드 블록으로 표를 넣는다.
- `run.sh`는 쿼리가 조회가 아니면 파일을 만들지도 보내지도 않고 멈춘다. 이것은 실수를 거르는 장치이고, 실행 자체를 막는 진짜 보장은 읽기 전용 DB 계정이다.

## 설정
- 설정: `~/.config/slack-report/.env`에 `SLACK_BOT_TOKEN`과 기본 `SLACK_CHANNEL`을 둔다(이 폴더의 `.env.template`을 복사해 채운다). 같은 이름의 환경 변수가 있으면 그것이 먼저다. 플러그인 폴더는 업데이트 때 새로 깔리므로 설정을 폴더 안에 두지 않는다.
- 봇 권한은 `chat:write`·`files:write`이고, 봇은 채널에 초대돼 있어야 한다. 토큰 내용을 출력하거나 대화에 옮기지 않는다.
- 설정이 없으면 `run.sh`가 설정 파일을 만드는 명령을 알려 준다. 그 명령을 사용자에게 보여 주고 토큰을 채워 달라고 한다.
